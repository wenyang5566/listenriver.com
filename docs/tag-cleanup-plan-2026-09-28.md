## 建議架構

保留五大分類，其中助人工作是主要收錄方向；會所模式是專題總入口，下面維持實習、工作日誌、工作手冊三個系列。未來與會所模式有關的閱讀筆記或非系列文章可以使用「會所模式」主題 tag，因此不建議現在直接刪除它。

三個系列名稱保留，不要求它們改成四字；四字一致是五大分類的命名決策，無需延伸到所有系列。只在「會所模式」專區內，可顯示「實習／工作日誌／工作手冊」短名稱；搜尋、全站入口與正式系列名稱保持完整，避免語境不明。

Hugo 的 taxonomy 本身是平面詞表，不會因同時標記「會所模式」和「會所實習」就自動建立父子層級；專題／系列關係應由現有 section 與導覽表達。參考 [Hugo Taxonomies](https://gohugo.io/content-management/taxonomies/)。此為本站內容與現有實作的建議，沒有必要立即增加新的 series taxonomy。

## 先處理的低風險項目

1. 統一既有系列連結：首頁與總覽已使用 `topic-entry-url.html` 指向 section；文章卡片標籤、文章頁標籤與「繼續探索」仍可能指向 `/tags/…/`。先盤點並逐組改到同一個可靠系列入口，保留標籤資料與舊頁。
2. 會所文章的系列、總主題與延伸主題分工：系列用明確的系列入口呈現；在會所專區內，卡片不必反覆列「會所模式」與同名系列。把有限的標籤位置留給真正延伸的概念，避免目前 `first 2 tags` 讓標籤順序決定讀者看見什麼。
3. 系列閱讀順序：核對編號、日期與前後篇；手冊 03 是草稿，公開目錄應如實顯示 01、02、04、05，不能自動補號或發布草稿。
4. 整理全站 tag 字典：註明主題、形式、系列、作品／人物及收錄準則；檢查近義詞的實際文章差集。41 個使用中的 tag 並不多，單篇 tag 也不應只因篇數少就刪除。

本階段不需批次改文章標籤。上述工作完成後，再決定是否把三個系列 tag 從後台移除；現有搜尋修正按 section 判定，不依赖這三個 tag。

## 後續移除系列 tag 時必須處理

- 先查所有模板、相關文章排序、導覽篇數、搜尋與 RSS 是否依賴該 tag，改由 section 取得系列資料。
- 保留主題 tag「會所模式」的收錄定義；不要把語音社群平台 Clubhouse 同名文章自動納入精神復健會所。
- `/tags/會所實習/` 等既有入口與分頁／RSS 需完整盤點，為可對應目的地設定直接 301。不同排序的 tag 分頁不能盲目對應同頁碼 section 分頁。
- 現有三個系列 tag 頁設定 `robotsNoIndex: true` 並 canonical 到 section，但這些不是 HTTP 301，不能當作網址迁移已完成。
- 移除後重新驗證舊路徑、內部連結、canonical、sitemap、RSS、搜尋召回與相關文章，才算完成。

## 作者需要決定的事

- 建議採「總主題＋三個系列」，不合併四者。若日後想合併日誌與手冊，應先決定兩者的內容定位，而非只因名稱都含會所。
- 手冊較像「做法與原則」還是「工作反思」？目前部分標題是反思性內容；可先補導讀說明，再評估是否改名，不急著搬網址。
- 後台系列 tag 是否移除？建議等前台入口一致與依賴盤點完成再決定。
