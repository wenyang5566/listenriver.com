## 判斷

現有分段捲動功能正常，建議保留；下一批優先統一手機深色 header 的色票。恢復門檻屬操作手感，可再試調，但不視為故障，也不直接覆寫先前刻意延長的設計。

## 現況與證據

- 先查 codebase-memory-mcp index_status，索引根目錄、分支與 HEAD 對應開始時來源；search_graph 定位 sticky header。header 模板有解析缺口，關鍵行為另讀目前 `static/js/custom.js` 與 CSS 確認。
- 桌機（861px 起）：向下累計 160px 收起分類列，400px 隱藏整個 header；向上累計 160px 恢復上層，440px 恢復分類列。精簡時上層仍約 82px 高，分類列不接收焦點與點擊。畫面未見不透明空白列；是否再縮上層高度屬次要選項。
- 手機 header（860px 以下）：向下累計 80px 隱藏。一般頁向上 32px 顯示；768px 以下文章頁向上 160px 先恢復底部 icon 工具列，480px 才恢復完整工具列與 header。
- 手機文章工具列：向下累計 160px 收文字，640px 整條隱藏。完整恢復後有 400ms 保護期，避免反彈立即收回。
- 手機文章深色畫面：header 呈冷黑，正文及底部工具列呈暖棕；與共用書刊色票不一致。這是截圖可見的色差，尚未定位最終生效的覆寫規則。
- 390／820／1440px，亮／暗模式，首頁及文章頁五個捲動階段共 60 筆尺寸資料，均無水平溢出。另直接檢視手機亮／暗文章與桌機亮色精簡畫面。
- 現有 `tests/scroll-navigation.spec.js` 的 10 項測試全部通過，涵蓋七種頁型、三種寬度、明暗模式、反彈保護、階段門檻、面板、鍵盤焦點、resize 與 reduced motion。

## 建議順序

1. 統一手機深色 header、搜尋面板及選單的暖棕底色，核對實際 computed style，再驗證明暗模式與面板開關。
2. 手機文章完整導覽恢復 480px 約為本次 900px 視窗的一半，若使用者希望更快找搜尋／選單，可縮短第二段恢復距離；保留第一段底部工具列及反彈保護。
3. 桌機先保留目前兩段收合。82px 上層可再試更緊湊的版本，但須避免改變 sticky 佔位造成閱讀跳動。

本輪只評估，未修改功能、提交或部署。使用本機 1314 Hugo 預覽與 Edge Chromium；截圖、原始資料及腳本在 Git 忽略的 `.tmp/sticky-audit/current-*`。手機為桌面瀏覽器的視窗模擬，未驗證實機 Safari、觸控慣性或正式站。未變更網站來源，因此未另跑建置；功能測試針對本機目前分支預覽。

## 後續試調：縮短恢復距離

使用者確認後，`static/js/custom.js` 的桌機恢復門檻由 160／440px 改為 80／240px；手機文章頁由 160／480px 改為 80／240px。第一段仍分別恢復桌機上層與手機底部 icon，第二段恢復完整導覽。手機其他頁的 32px、向下收合門檻、400ms 反彈保護均維持。

測試同步更新恢復距離，桌機檢查 79／80px 及 239／240px 邊界，手機文章檢查 77／80px 及 237／240px（配合小於 3px 的微動累積）。原 1314 記憶體預覽未反映新 JS，因此建立獨立 1315 預覽重測；9 項通過後，修正桌機測試反彈座標並補驗該項通過，合計 10 項驗證完成。Hugo 0.166.0 建置與 git diff --check 通過；既有語言設定棄用警告仍在。未提交或部署；深色 header 色差留待下一批。
