# Awwwards／FWA 對照研究與可移植原則

查證日期：2026-10-13（Asia/Taipei）。用途：listenriver.com 全站深度評估的外部標竿證據。本文只提出評估與建議，沒有修改網站、提交或部署。

## 證據方法與限制

先以 Web 搜尋定位官方頁面，再以 Codex In-app Browser 實際讀取官方評選頁與作品原站。Web.open 對部分 Awwwards 頁面逾時，FWA 動態頁只回傳空正文；以下關鍵規則與日期以官方網站在瀏覽器顯示的文字確認。資料來源只採 Awwwards、FWA 和作品原站。

「官方事實」指評選頁、得獎詳頁明示；「原站觀察」指本次瀏覽確實看到的畫面、文字或操作；「本站建議」是設計判斷，不能解讀為主辦單位要求或獲獎保證。本輪沒有完整測試參考作品的手機、效能、鍵盤、讀屏或 reduced-motion 行為。參考作品得獎當年的狀態也可能與今天不同。

## 官方標準：不能把兩個獎項當作同一套公式

[Awwwards 官方 Evaluation System](https://www.awwwards.com/about-evaluation/) 的當前頁面確認四項權重：Design 40%、Usability 30%、Creativity 20%、Content 10%。作品審核後至少交給 18 位評審，排除離平均最遠的 3 筆評分；一般投票期 5 天。Honorable Mention 的當前說明為評審分數至少 6.5，Site of the Day 給評審評分最高的作品；並未提供可用來保證本站獲獎的固定分數。SOTD 得主另交開發評審，依 Developer Guidelines 超過 7 分才授予 Developer Award。每月分數最高的 8 站進入 SOTM 再審。以上是 2026-10-13 官方頁文字，不沿用網路二手文章中不同的舊規則。

[FWA 官方 About FWA](https://thefwa.com/about/about-fwa/) 強調創造力、創新和推進數位設計／技術可能性，媒介不限定網站；官方說明每日由評審選 FOTD，每月選 FOTM，每年選 FOTY，PCA 為年度公眾票選。本次已讀頁面沒有公布 Awwwards 式的四項固定權重，因此本報告不替 FWA 編造權重、及格線或本站獲獎機率。

對本站的含義是：Awwwards 方向應以「原創主張＋全站一致的精工＋可使用性」評估；FWA 方向更需要說明「這個數位體驗讓讀者做到／感受到什麼，只有一般文章列表做不到」。這是本報告的判讀。官方頁面沒有規定必須使用 WebGL、3D、特定動畫框架或更換 Hugo。

## 適合 listenriver 的差異化方向

以下建議基於本站已知定位：中文個人書寫、復元、閱讀與助人工作；五類文章加會所專區；奶油紙色、陶土／河青、宋體字標、河流標誌與 SVG 兔子。這些是本專案給定背景，個別現況仍以主報告的正式站／來源查驗為準。

### 1. 讓「聽河」成為閱讀方法

可探索的概念是「文字像河，讀者選擇停靠的地方」。以讀者的需要安排少量策展路徑，例如「從這裡開始」「關於復元」「讀一本書之後」「助人的現場」。不新增另一套全站分類，也不改文章 URL。每條路徑由作者挑選 3–6 篇文章，加一段說明它們為何相連。

河流因此有功能：引導讀者從一篇走到下一篇，而不是單純畫在背景。桌面可以有節制的 SVG 線條與節點；手機可用垂直列表；減少動態模式仍保留全部目的地。是否採用需先以一條真實內容路徑驗證。

### 2. 用編輯與藝術指導提高每一頁的完成度

已選定的中文宋體＋英文 Merriweather 是既有方向，應保留並完成全站規格。提升來自標題、導語、引言、圖說、註釋、正文、文末延伸的比例和節奏，而不只是增加字型。將同一種內容在首頁、分類、文章、搜尋、關於頁之間建立可辨認的視覺層級。

優先製作少量專屬素材：作者手稿、河岸近景、一張有清楚敘事目的的主圖，以及由既有河標誌衍生的章節細節。圖片選擇應回答「這段文字為什麼需要它」，避免所有文章套同一張抽象圖。

### 3. 一個可記住的互動，服務一個具體問題

可先驗證「當我讀完這篇，接下來去哪裡」：文末以同一條河線連起下一篇／同專題／回到目前路徑，並給一句選讀理由。其成功條件是讀者更容易續讀，而不是動效數量增加。

如果未來要更偏 FWA，可另做一個作者真正投入的完整數位敘事專題，有自己的視覺素材、節點、首尾與可以描述的互動創新；其餘博客維持閱讀效率。這是參展策略的選項，不代表必須拆站、換框架或增加 3D。

### 4. 把狀態和退出方式當作設計內容

參考作品提示了入口、章節和替代閱讀的重要性。本站的抽屜導覽、搜尋、音訊、圖片檢視、互動按鈕若存在，應都有清楚的焦點、關閉、錯誤和無內容狀態。動畫有停止／減少方案，聲音需使用者主動開啟，頁面內容不依賴動畫播放完成才可讀。所有專題都能回到正常文章入口。

這些是本報告建議的驗收條件，不能冒稱為已通過的官方認證。

## 建議的評估與製作順序

1. 先完成正式站與未發布版的差異盤點、找文／閱讀／鍵盤／手机／深色驗收；不能只以首頁截圖代替全站完成度。
2. 選定一句網站主張與一條真實的文章閱讀路徑，做首頁、列表、文章三種版型的連貫設計原型。
3. 用少量專屬圖像與一個功能明確的河流互動，驗證其能提升理解和續讀；保留既有分類、內容與網址。
4. 以核心讀者測試、行為證據、效能與可存取性驗收決定是否擴展。投稿前再查主辦單位規則；不以本報告的內部評估分數冒稱評審分數或獲獎機率。
