# Listen River 分類與閱讀入口完整稽核

稽核日期：2026-09-25。範圍：正式站、目前工作目錄、Hugo 全新建置、分類與標籤集合、導覽、會所專區、搜尋、歷史入口及搜尋引擎設定。本輪僅分析與產出報告，沒有修改網站內容、版型、設定或部署。

**整體判斷：五大分類可以保留，真正需要優先整理的是各種入口的分工與資料來源。** 目前分類、標籤、系列、實體目錄和會所專區各自有一套規則；名稱、文章集合、數字與點擊目的地有時不一致。讀者因此可能找得到入口，卻無法預期進去會看到哪些文章。這比單純「標籤太多」更重要。

本報告沿用 [先前決策](../taxonomy-2026-09-20/decision-plan.md)：保留五類、成為自己及獨立病痛分類；閱讀與筆記已決定改稱閱讀與觀看，但網址策略尚未定案；日常名稱尚未定案；會所已併入助人工作導覽。沒有把舊四類提案重新當成你的決定。

**三、優先修正的功能與入口問題**

優先級：P1＝明確誤導或阻斷找文章，先修；P2＝閱讀結構與維護問題，下一輪整理；P3＝編輯完善。不使用沒有依據的 SEO 分數或估計流量損失。

**01｜P1：「全部文章」漏掉全部 30 篇會所文章。**

[全部文章](https://listenriver.com/blog/) 顯示 196 篇、20 頁，來源只包含 blog；首頁「最新文章」也只從 blog 取文。因此網站最新的 2026-08-19 會所文章出現在會所區，但「最新文章」仍從 2026-05-17 電影心得開始。首頁另設會所區本身合理，問題在全站性的名稱與實際集合不符。

證據：`layouts/index.html:2–15`、`layouts/_default/list.html:39`、`content/blog/_index.md`。建議所有稱為「全部文章」「全站文章數」的入口，使用 blog 與 clubhouse 的去重聯集；首頁若刻意分開，改為「最新一般文章」等明確名稱，或統一最新文章來源。

**02｜P1：五類架構與「六大主題分類」互相衝突。**

[分類總覽](https://listenriver.com/categories/) 標題仍寫「六大主題分類」，將會所與助人並列；header 已將會所放在助人下面，資料層則只有五個 category。首頁六張「探索主題」卡片可以是五類＋一專區，但分類總覽不能繼續暗示它們是互斥的六大主分類。

建議保留五類，會所明確標「專區／系列」，文章數不用相加。分類總覽 196 應改為獨立文章總數 226。證據：`layouts/partials/taxonomy-content.html:10,493,508`、`data/taxonomy-landing.yaml`、`layouts/partials/site-nav-items.html`。

**03｜P1：看似子分類的入口，實際跳到另一個範圍。**

| 畫面上的位置 | 入口 | 全站 tag 篇數 | 屬於該主分類的篇數 | 問題 |
| --- | --- | ---: | ---: | --- |
| 日常書寫卡片 | 講座筆記 | 9 | 0 | 與卡片分類完全不相交 |
| 病痛經驗卡片 | 正念的河流 | 21 | 0 | 與卡片分類完全不相交 |
| 日常書寫下拉 | 詩的語言 | 5 | 0 | 五篇全在病痛經驗 |
| 助人工作下拉 | 家族治療 | 7 | 0 | 七篇全在閱讀與筆記 |
| 閱讀與筆記下拉 | 講座心得 | 3 | 0 | 兩篇助人、一篇日常 |
| 閱讀與筆記下拉 | 講座筆記 | 9 | 4 | 另五篇在助人工作 |
| 助人工作下拉 | 創傷知情 | 5 | 2 | 另三篇在閱讀與筆記 |

這些 tag 的跨類用途可以是合理的；**有問題的是把「跨類主題」呈現成「本分類的下一層」而沒有說明。** 首頁日常卡片推薦講座筆記、header 卻推薦素描與詩，也顯示入口設定已分岔。

此外，[成為自己](https://listenriver.com/categories/成為自己/) 內的「正念的河流 9」點下去會看到 [全站 21 篇](https://listenriver.com/tags/正念的河流/)；「成為一個人 10」則跳到 14 篇。數字計算的是本類交集，URL 卻指向全站集合。同樣現象也存在於 tag 頁回到 category 的相關分類連結。

建議先決定每個區塊是「本類篩選」還是「延伸主題」。前者必須限制集合；後者清楚寫「跨分類」，並標全站篇數，或寫「本類 9／全站 21」。不要為了讓選單看起來像樹狀，就把合理跨類文章硬搬家。

**04｜P1：同名 category 與 tag 差很大。**

| 名称 | Category | Tag | 差異 |
| --- | ---: | ---: | --- |
| 助人工作 | 56 | 18 | tag 是 category 子集，少 38 篇，含全部 30 篇會所 |
| 病痛經驗 | 27 | 5 | tag 是 category 子集，少 22 篇 |

在分類卡片點標題與點同名 #tag，會进入不同集合；文章上也可能同時出現兩個同名標記。讀者不應需要懂 category/tag 才知道自己看的是全部還是部分。

建議先定義這兩個 tag 是否具有獨立意義。若只是歷史遺留，讓同名主入口回到 category；若代表特定反思類型，需以能區分的名稱和說明呈現。不能直接聲稱它們是完全相同的重複集合，亦不應未核對就批量刪除。

**05｜P1：會所排序把新文章藏在末頁。**

[會所專區](https://listenriver.com/clubhouse/) 第一頁是 2023 年文章，2026 年最新內容位於 [第 4 頁](https://listenriver.com/clubhouse/page/4/)；首頁會所區、同名 tag 與子區則偏向新到舊。根因是 `layouts/clubhouse/categorylike.html:2` 先依日期降序，又 Reverse 成升序，之後先分頁，再由 GroupByDate 對頁內分組排序；結果既不像全站一致的新到舊，也不是簡單連貫的舊到新。

其「近期值得先看」卻抽到 2023 年最早的三篇。建議一般列表統一新到舊，若希望從實習開始讀，另外標為「從這裡開始」，使用明確策展順序。

**06｜P1：搜尋無法替代標籤入口，而且有明顯同名搜尋漏找。**

正式站直接搜尋 API 實測：

| 查詢 | 搜尋結果 | 對照 |
| --- | ---: | --- |
| 會所工作日誌 | 9 | 該 tag／子區有 19 篇；結果為日誌 11–19，1–10 未出現 |
| 會所模式 | 9 | 該 tag／專區有 30 篇；返回同一批日誌 11–19 |
| 書摘 | 62 | tag 為 28 篇；全文提及也會命中，不能用作精確篩選 |
| 助人工作 | 74 | category 為 56 篇、tag 為 18 篇，三種集合不同 |
| 正念的河流 | 21 | 本次與 tag 篇數一致 |

索引本身宣告 227 頁，不能因此說所有找不到的文章都「沒被索引」。查詢詞切分、生成 HTML 的文字邊界與 metadata 都需要另做定位；本次確定的是搜尋結果不能可靠找全同名主題。`filters()` 實際回傳 `{}`，版型也沒有 category/tag 的 `data-pagefind-filter`。

搜尋頁雖寫「搜尋文章、分類、主題」，但分類／標籤／section 頁的 main 被標成 `data-pagefind-ignore`，所以目前主要是搜尋文章中出現的分類文字，並非搜尋那些總覽入口。建議精確分類由 filter／主題建議連結處理，全文搜尋另行保留，並用「會所模式 30、日誌 19」作回歸案例。依據：[Pagefind 索引規則](https://pagefind.app/docs/indexing/)、`layouts/_default/baseof.html:28`、`layouts/_default/search.html`。

**07｜P1：舊助人入口確實導向 404。**

即時實測：`/blog/邁向助人工作/` → HTTP 301 → `/blog/助人工作/` → HTTP 404。該目錄內文章存在，不代表資料夾自動有列表頁；目前沒有相應 `_index.md`。見 `static/_redirects:3–4`。

建議舊集合入口直接轉到有效的 [助人工作分類](https://listenriver.com/categories/助人工作/)，而不是不存在的目錄列表。這是已存在的歷史入口问题，並非目前 header 全面壞掉。

另有較次要的 `/404.html` → 301 `/404/` → 308 `/404` → 200 狀態異常，應與 `/:path.html` 的廣泛規則一起檢視。它不是一般分類連結失效，但不能讓 404 頁本身被當正常內容。

**四、結構與內容層需要整理的問題**

**08｜P2：會所共四組 section/tag 雙入口。**

| 主要區段頁 | 同名標籤頁 | 當前文章集合 |
| --- | --- | ---: |
| `/clubhouse/` | `/tags/會所模式/` | 同為 30 |
| `/clubhouse/會所實習/` | `/tags/會所實習/` | 同為 7 |
| `/clubhouse/會所工作日誌/` | `/tags/會所工作日誌/` | 同為 19 |
| `/clubhouse/會所工作手冊/` | `/tags/會所工作手冊/` | 同為 4 |

header 走 section，首頁代表標籤、文章 chips 與相關主題走 tag。同一主題因此有兩種版型、介紹、排序或分頁體驗。三個子 tag 雖 canonical 到 section，依舊回傳 200 並顯示各自列表；canonical 不會將訪客轉走。會所模式 tag 則 canonical 到自己。

建議以既有 clubhouse 四個入口作主要閱讀目的地，統一站內連結；tag 可繼續作文章歸屬資料。是否將舊 tag 網址轉址，需要先核對分頁與 RSS，不能只改首頁 URL。另 `content/clubhouse/_index.md` 說來源為 tag「會所」，實際模板從 section 遞迴取文，當前 tag 是「會所模式」；該說明已過時。專區側欄寫「其他主分類／五大分類」，實際列三個會所子區，也應更正文案。

**09｜P2：電影與電影心得高度重疊，但不能直接刪一個。**

兩者分别 30、32 篇，交集 29，聯集 33。只在「電影」：〈阿鼻〉。只在「電影心得」：〈如何看待暴力〉、〈夏日大作戰〉、〈綠洲〉。也就是〈阿鼻〉雖在閱讀分類、電影心得目錄中，卻進不了 header 的電影心得 32 篇入口。

建議將電影心得作為單一主要形式入口，先逐篇確認這四個差集，至少核對〈阿鼻〉的漏標；保留「電影」歷史網址的去向。〈如何看待暴力〉可以保留日常 category 與電影心得 tag 的跨類關係，不因目錄不同就判定分錯。

**10｜P2：標籤混合形式、理論、系列與作品，但沒有可維護的字典。**

- 形式：書摘、閱讀心得、電影心得、講座筆記、講座心得、詩的語言。
- 主題／理論：創傷知情、開放式對話、家族治療、親密關係、現象學。
- 系列／長期線索：會所實習、會所工作日誌、會所工作手冊、聆聽疼痛計畫、素描、正念的河流。
- 作品／作者：午夜福音、聆聽疼痛、障礙政治、一行禪師、是枝裕和等。
- 意義未分清的同名項：助人工作、病痛經驗。

同一個 tags 欄位容納上述用途並非技術錯誤，現在不必再建三套 Hugo taxonomy。應先建立人可讀的用途字典，規定哪些能上導航、哪些只供串連。41 個使用中 tag 只有 18 個有專用 `_index.md`；其餘 23 個由 Hugo 自動生頁，並非缺頁，但缺少個別說明。兩個被高頻使用的「蟹足腫病痛」「詩的語言」也沒有自己的介紹頁檔案。

完整 41 項與處理建議見 [標籤字典](tag-dictionary.md)。特別不要誤合併：

- 「聆聽疼痛」4 篇是書籍相關，「聆聽疼痛計畫」12 篇是計畫內容，交集為 0。
- 「成為一個人」14 篇已有 Rogers／人本取向的定義，不等於成為自己分類 27 篇。
- 「詩的語言」目前五篇全為病痛書寫；詩是形式，不需要為了日常選單而搬動主分類。
- 日常兩篇標題含 Clubhouse 的文章談的是語音社群平台，不能僅依名稱移入精神復健會所專區。

**11｜P2：同一篇文章在不同入口顯示成不同身份。**

`content/clubhouse/會所工作日誌/17將言語視為符號/index.md` 的 `title` 是「會所工作手冊」，`displayTitle` 是「將言語視為符號」，`seriesLabel` 是「會所工作日誌 17」，category/tag 又正確屬日誌。

首頁和單篇使用 displayTitle，分類／標籤／子區部分模板直接用 Title，於是日誌列表真的會出現一篇名叫「會所工作手冊」的文章。這是誤填的原始 title 加上不同模板規則共同造成，應同時修正。先核對同類 title/displayTitle 欄位，再使用共通的顯示名稱函式；不需要因此改網址。

**12｜P2：病痛「全部文章」其實是個人書寫 15 篇。**

病痛分類總計 27，模板有意將聆聽疼痛計畫 12 篇抽成獨立系列入口，主列表剩 15。系列入口存在，文章沒有丟失；但主列表標題仍是「全部文章」。建議改「個人病痛書寫（15）」並標出「另有聆聽疼痛計畫 12」，或者真正提供 27 篇的全部檢視。此處不是分頁漏資料，應修正文案及閱讀選擇。

**13｜P2：實體資料夾被混用為分類、形式與系列。**

含草稿共有 16 種文章二級目錄，已發布使用 15 種；主分類只有 5 個。書摘、閱讀心得、電影心得是形式；成為自己、病痛經驗、日常書寫是領域；聆聽疼痛計畫、會所日誌則是系列。作者因此要同時決定「存在哪裡」「category 是什麼」「tag 要填什麼」，而網址又跟實體路徑綁定。

例如疼痛書寫目錄仍有 6 篇，卻沒有現行「疼痛書寫」tag；`content/blog/詩的語言/` 三篇都是草稿，但已發布的詩 tag 来自另一個目錄。這些不是需要刪除的垃圾資料夾，而是歷史組織方式與現行導覽不同。

建議先固定既有路徑與圖片 bundle，明確以 front matter 決定公開分類；作者規則建立後再決定是否有必要整理目錄。搬目錄會牽動網址、圖片與互動識別，不應成為整理分類的第一步。

**14｜P2：導航資料分散，修改一處無法保證全站一致。**

| 檔案 | 目前作用 |
| --- | --- |

首頁／header 次序是「閱讀、日常、自己、病痛、助人」，分類總覽卻是「閱讀、助人、病痛、自己、日常」。同名入口編號亦不同。另保留 `data/featured-tags.yaml`、舊 header helper、homeTagAxes 等設定；部分 helper 在目前 layouts 內沒有被呼叫，不應誤當現行 header 的來源。

建議將主分類 id、顯示名稱、URL、排序、入口種類集中成一份資料；明確區分現役與未使用 helper。`scripts/taxonomy_migration.py` 仍使用「工作者反思／自我成長」等舊名稱且只以 BLOG_ROOT 為基礎，不能拿它當目前分類的修復工具直接重跑。

**15｜P2：返回脈絡與連載順序不夠明確。**

blog 文章 breadcrumb 大多為「首頁／全部文章／本文」，沒有帶回目前主分類；文章上方的 category chip 提供了另一條返回路徑，因此不是完全無法回分類。會所則有「首頁／會所模式／子區／本文」，兩區對層級的表達不同。

上一篇／下一篇使用 `PrevInSection/NextInSection`，不是按 seriesLabel 或數字排序。已實測《午夜福音》E3 前一篇是《割腕的誘惑》閱讀心得，下一篇是〈一種抵達經驗的方式〉。這可以是時間序導覽，但不能當作「同系列下一篇」。建議標明全站／同區前後文，重要連載另外給明確系列目錄及順序。

**16｜P2：主題推薦目前受全站熱門度與時間排序支配。**

分類／tag 頁上的「先讀這幾篇」多是直接取最近 3 篇，並非編輯挑選；分類 `_index.md` 裡又有另一組手動導讀，可能出現兩組「先讀」。分類相關 tag 先依全站 ByCount 選擇，再顯示局部交集：病痛頁因「助人工作」全站較常見，把本類僅 1 篇的它放在 12 篇疼痛計畫前面。

「常一起出現」也由全站排行決定，未必是與當前 tag 最相關的順序。建議分開「編輯推薦」與「最新文章」，相關主題按當前集合的關聯量或人工權重，避免廣義 tag 排擠真正有辨識度的線索。

**17｜P2：重要 tag 的搜尋引擎策略沒有分層。**

所有 tag 頁目前都 noindex，且未進 sitemap；部分 `_index.md` 雖寫 `robotsNoIndex: false`，`head.html` 後續仍因 Section=tags 設成 noindex。會所三個子 tag 甚至輸出 noindex,nofollow 並 canonical 到 section。

不讓一般標籤被索引可以是有意識的策略，不能說是錯誤或因此斷言網站排名受損。但「蟹足腫病痛、聆聽疼痛計畫、正念的河流」若被當成對外重要的閱讀入口，現在無法靠這些 tag 頁本身作 Google 搜尋入口，需要先決定是否為少數策展頁開例外。也不能只改 front matter false 就認為解禁。

正規頁選擇應使用一致的主要 URL 與內部連結；不要將 noindex 與 canonical 當成同一種操作。參考 [Google canonical 指引](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls) 與 [noindex 說明](https://developers.google.com/search/docs/crawling-indexing/block-indexing)。本次沒有 Search Console，無法判定 Google 實際收錄、選定 canonical 或流量變化。

**18｜P3：日常分類仍被定義成難以歸類的容器。**

目前描述有「不一定被分類完成」「比自我成長更保留未完成感」，也殘留「自我成長」舊名稱。这讓作者容易按完成度、篇幅或猶豫程度來分日常，而非按文章內容。建議以正面的收錄範圍定義：生活觀察、實作、工具、旅行、創作等；短文和未完成感也可以在病痛或成為自己，不必因此進日常。

**六、建議修正次序與驗收條件**

1. **先讓名稱與集合一致。** 修正全部文章／總數、五類＋會所的標示、零交集卡片、會所排序、病痛 15＋12 文案、日誌17錯誤 title、已證實404。驗收：全站總數226；會所30不重複相加；「全部」入口真的包含預期集合；相關數字能解釋點擊後的差異。
2. **再收斂 tag 與入口。** 先處理電影四個差集、兩個同名 category/tag、會所四組雙入口與 Shamless；不碰合理跨類 tag。驗收：主要名稱只有一個可預期目的地，保留舊 URL 的有效去向，無 alias 迴圈。
3. **集中維護資料，補編輯規則。** 用同一份分類資料生成 header、卡片、地圖與順序；標籤字典記錄用途與收錄邊界；把舊 migration 工具標為歷史用途。驗收：改顯示名／排序只需改一個資料來源，不留下舊標題或死入口。
4. **補搜尋與系列閱讀。** 以精確 filter／入口建議支援 category/tag；另定位中文查詢的漏找問題；有序系列不依賴全區日期相鄰。驗收：會所模式30、日誌19可由明確主題操作完整取得；一般全文搜尋則不要求等於tag數量。
5. **最後才決定 URL 或 SEO 調整。** 閱讀改名可以先只改顯示名並保留既有路徑；若改路徑，需處理舊首頁、分頁、RSS與歷史alias。必要時再定義少數可索引策展tag。搬文章不應與改分類名稱綁成同一件事。
